# Deployment

SecurePass runs the same way everywhere: a Docker image, a PostgreSQL database and a few
environment variables. This page covers running it on your own computer and on Render's free plan.

## Environment variables

| Name | Needed | Meaning |
| --- | --- | --- |
| `SECRET_KEY` | always | Random value that signs sessions and reset links. In production it must be at least 32 characters. |
| `DATABASE_URL` | for PostgreSQL | `postgresql://user:password@host/dbname`. Without it the app uses a local SQLite file. |
| `FLASK_ENV` | always | `production` behind https, `development` for plain http on your own computer. |
| `PROXY_HOPS` | behind a proxy | How many reverse proxies sit in front of the app. `1` on Render. Only then are `X-Forwarded-*` headers trusted. |
| `WEB_CONCURRENCY` | optional | Number of gunicorn worker processes. Keep `1` while rate limits live in memory. |
| `RATELIMIT_STORAGE_URI` | optional | `memory://` by default. Use a shared store such as `redis://...` when running several workers. |
| `PUBLIC_URL` | optional | Public address used inside password-reset emails, for example `https://securepass.onrender.com`. |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `MAIL_FROM` | optional | Real outgoing email. Without `SMTP_HOST` no email is sent, and in production the reset link is not shown anywhere. |

Secrets live only in the environment (`.env` on your computer, the dashboard on Render). The file `.env`
is listed in `.gitignore`, and `.env.example` holds only placeholder values
(`test_env_example_holds_no_real_secret`, `test_the_real_env_file_is_never_committed`).

## On your own computer with Docker

1. Copy `.env.example` to `.env`, then replace `SECRET_KEY` and `POSTGRES_PASSWORD` with random values.
   `python -c "import secrets; print(secrets.token_hex(32))"` makes a good one.
2. Run `docker compose up --build`.
3. Open http://localhost:8000. On first start the container applies the migrations and adds the demo data.
4. Create an administrator: `docker compose exec web flask --app wsgi create-admin`.

The database has no published port, so only the web container can reach it
(`test_the_database_port_is_not_published_by_compose`). The image runs as a non-root user
(`test_dockerfile_does_not_run_as_root`).

## On Render (free plan)

1. Push the repository to GitHub.
2. In Render choose New, then Blueprint, and pick the repository. Render reads `render.yaml`, which creates the
   web service and the PostgreSQL database. `SECRET_KEY` is generated by Render and `DATABASE_URL` comes from the
   database itself (`test_render_blueprint_generates_the_secret_key_and_keeps_the_database_private`).
3. Wait for the first deploy. The container applies the migrations, adds missing demo data and starts the server
   (`test_entrypoint_applies_migrations_before_starting_the_server`).
4. Open the Shell tab of the service and run `flask --app wsgi create-admin`. There is no default administrator.
5. Optional: add `PUBLIC_URL` and the `SMTP_*` variables in the dashboard to send real reset emails.

Render checks `/healthz` to know the app is alive. It answers only `{"status": "ok"}` or
`{"status": "unavailable"}`, never a detail (`test_health_check_says_ok`,
`test_health_check_says_unavailable_without_details`), and it answers over plain http inside Render's network
while every other page still redirects to https (`test_health_check_works_over_plain_http_in_production`).

### Limits of the free plan

- The web service sleeps after 15 minutes without visitors and takes about a minute to wake up.
- The free database is 1 GB and **expires 30 days after it is created**, with a 14-day grace period before it is
  deleted. Make a backup before it expires (below) and restore it into a new database.
- With one worker the rate limits are kept in memory and reset when the service restarts.

Check Render's current free-tier terms before relying on these numbers.

## Backups

```
DATABASE_URL="postgresql://user:password@host/dbname" sh scripts/backup_db.sh
```

This writes `securepass-backup-<date>.dump` (ignored by git). The file holds every account and booking, so keep
it private. To restore into a new, empty database:

```
pg_restore --clean --if-exists --no-owner --dbname "$NEW_DATABASE_URL" securepass-backup-<date>.dump
```

Then point `DATABASE_URL` at the new database and redeploy.

## Tests on PostgreSQL

Continuous integration runs the whole test suite twice: on in-memory SQLite and on a real PostgreSQL server
(`pytest -p tests.postgres_isolation` with `TEST_DATABASE_URL` set). The PostgreSQL-only checks in the tests folder
also confirm that the migrations build exactly the schema the models describe
(`test_migrations_build_exactly_the_schema_the_models_describe_on_postgresql`) and that the database itself
refuses duplicate flights and flights to unknown airports. A third job builds the Docker image, starts it
against PostgreSQL and calls the health page.
